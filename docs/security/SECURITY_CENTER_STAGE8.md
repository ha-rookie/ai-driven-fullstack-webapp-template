## Slice I: genuine OSV advisory lookup of the reviewed runtime lock inventory (read-only)

The global security Finding Provider remains `not-connected`; GitHub CI step status can prove an observed control failure but cannot prove package vulnerability counts. The existing production dependency workflow runs a vulnerability audit, but public GitHub workflow metadata cannot safely return its complete raw alert list. The GitHub Dependabot alerts API requires a separate authorized security-alert reader; **this slice must not add GitHub/Cloudflare Secrets, token permissions or remote resources**.

An administrator may explicitly request a **read-only, bounded** OSV.dev `POST https://api.osv.dev/v1/querybatch` lookup using **all 12 non-development/non-optional runtime package-lock v3 entries from the reviewed main baseline**, including the nested second `tslib` version as a separate location. The source inventory is fixed in `config/security-runtime-dependency-inventory.json` and verified against the lockfile by a unit test so any dependency drift invalidates CI rather than silently widening/forgetting packages. A zero means **no advisory IDs returned by OSV for exactly this lock inventory and check time**, NOT an assurance that all application/infrastructure dependencies or security classes are clean.

The result intentionally uses a **separate advisory observation contract** (`runtime-lock-only`) rather than pretending to know the missing `SecurityFinding` severity, open/fixed lifecycle, exploitation potential, or SCS eligibility. The provider returns only validated advisory identifiers matched to an immutable package reference and a check timestamp. It cannot change the global `findings: {state:"not-connected",items:null,verifiedCount:null}`, the global Gray posture or SCS requirement status. Unknown provider IDs, partial/paginated responses, short/missing/extra results, duplicate IDs, unexpected content types, oversized responses, provider failures and local/test offline environments produce `unavailable`, **not** a trusted zero. For verified results, link only to the fixed OSV advisory host with a strict identifier grammar; never render arbitrary description/exploit details/URLs.

The existing Security Center route adds just one fixed query mode `dependencyAdvisories=runtime`, checked after session authentication plus independently scoped `system_admin` authorization. GET-only, no-store; the on-demand user button avoids automatic external calls and cache/backoff bounds repeat requests. This is a concrete external vulnerability-data lookup for the *lock snapshot* only; it does not replace the reviewed CI audit, Dependabot, live Worker dependency inventory attestation, a genuine cross-source Finding feed or the SCS evidence freshness contract. Browser E2E uses a synthetic API fixture; without deployed code it is not a claim of an executed Preview/Production OSV request.

## Slice B: observe existing CI execution without inventing Finding evidence

After the separately approved #732 merge, the next incremental change connects the existing four public GitHub Actions workflows through a server-owned, GET-only reader. The existing endpoint authenticates and independently authorizes the fixed WORKHUB scope **before** invoking that reader. The repository and workflow filenames are allowlisted in code; request parameters, Cookies and credentials cannot choose a target or enter an outbound request. No workflow, scanner, token, binding, database, or remote resource is added.

The reader requests at most five runs per workflow. It validates repository/path identity, positive run IDs, exact SHA, controlled execution states and timestamp chronology, then reuses #727's source snapshot normalizer. Raw provider records, actor names, logs, artifacts and arbitrary URLs are discarded. The UI constructs run links only from the fixed repository and validated numeric run ID. It displays the observed run's SHA and event: these may be PR code and **are not the deployed application or current main**.

CI execution and Finding evidence remain separate axes. A successful workflow has `checkedFindingCount: null` and `freshness: unknown`. A failed or inaccessible source cannot become Green. `latestSuccessfulRun.updatedAt` means the update timestamp of a successful run **within the fetched five-run window**, not its exact job completion time, the all-history last success, a successful Finding assessment, or an SCS evidence freshness date. The previous success may reference a different SHA and is displayed separately from the latest state. If no success is found in that bounded window, the UI says so rather than claiming no check has ever succeeded.

Each GET rejects redirects, has a fifteen-second timeout (matching the existing runtime-evidence collector budget) and a 256 KiB streaming body limit, and uses no authentication header. Independent source failures produce `unavailable` only for that source. A per-isolate single-flight cache holds both successful metadata and failure results for at most five minutes, limiting retries to four GETs per five minutes per isolate; the original fetch time remains visible. Refresh failure discards previous success rather than representing it as current. This is a quota-saving cache, not a durable source of truth or a cross-isolate rate limiter. Public GitHub rate limits can still make reads unavailable. Local/Test never automatically calls GitHub; synthetic unit/browser fixtures are explicitly test-only.

Validation covers the GET allowlist and credential boundary, malformed/oversize/redirect/timeout failures, partial availability, success versus unknown Finding count, bounded historical success, cache expiry and authorization-before-read. Browser acceptance covers execution/failure/history metadata and unsafe API responses. A one-off live public API read is separate integration evidence; CI/browser fixtures are not Production scans. Original #420 acceptance remains 2/11 on main until an approved merge and evidence-by-condition review. Verified Findings, actual Finding freshness, SCS trace, remediation and formal ST #694 remain incomplete.

Provider contract: [GitHub REST workflow runs](https://docs.github.com/en/rest/actions/workflow-runs#list-workflow-runs-for-a-workflow). GitHub's `updated_at` is deliberately not renamed to a completed-check timestamp.
